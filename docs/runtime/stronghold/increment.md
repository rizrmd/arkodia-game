## Contract compatibility

The new loader explicitly supports only v2 `arkadia.stronghold-prefab.v1` and `arkadia.asset-manifest.v1`. The presentation extension retains original character metadata, picker labels and frame manifest, parsed original MSDF metrics, UI highlight bundle, original map/gate metadata, derived original placement list, and exported fresh-camp collision columns. The runtime checks the exact presentation profile, hero identities, clips, image dimensions, frames, paths, digest bindings, navigation values and bounded budgets. All document/asset SHA-256 checks and asset byte-size checks occur before activation. Four bounded download workers and response timeouts prevent unbounded fetches. Public paths are constructed against the fixed allowlisted gateway; content cannot provide arbitrary URLs or credentials.

The original six-view atlas frames omit `row`, `col` and `source`, which the current audited character-atlas schema requires. An attempted ordinary Save was correctly rejected with 422. Those fields were not fabricated, and the API/schema was not changed or redeployed. The exact original metadata instead lives in the explicitly supported extensible presentation manifest, with original provenance. This is not automatic v1/v2 conversion or general character-atlas support. A future first-class character adapter should extend/test the audited schema to represent both original atlas shapes deliberately.

The publisher transfers the exact checked-out assets into a private import staging folder, then uses ordinary asset POST, optimistic draft Save/reload and publisher release POST. The live original asset cache can transform PNG bytes, so importing fetched production bytes failed the source-hash check; the importer retained that check. Draft comparison uses semantic object equality because PostgreSQL JSONB normalizes key order. Bounded upload workers and retry of explicit transaction-conflict responses preserve idempotency. Tokens are read only inside the existing Content API sandbox's private config, never copied into source or browser requests. The API process and schema are unchanged.

## Responsibility split

- Reusable runtime: public-release integrity loader (`published.ts`), input foundation, bounded swept A* (`navigation.ts`), Pixi lifecycle and asset cleanup. Routing accepts injected collision/map/passage functions and knows no Arkodia economy or save keys.
- Arkodia adapter: original ChooseHero/ornate frames/MSDF shader and tokens, original NixieFX UI highlights; fresh camp assembly, 2:1 materials, scenery shear/pivots/depth, hero idle/move direction selection and mirroring, original 120/90 movement ellipse and collision/gate rules, original pan/follow dead-zone and scale, thumbstick art/input easing, local preference/position adapter.
- Content: immutable prefab, presentation metadata, exported collision columns, exact artwork/atlases/fonts/particle textures. No source URL fallback or original-game dependency runs in the consumer.
- Server/save: remains separate. No fake multiplayer, economic transactions, cloud save, cross-origin save import or authority is supplied. Runtime device preference and release-scoped per-hero position use new keys under `arkodia.runtime.*`; original production origin storage remains untouched.
