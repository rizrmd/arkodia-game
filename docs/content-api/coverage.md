## Coordinates, units and identities

- Environment map placements use absolute map tiles. The current map is 936×936, 3 metres/tile; Stronghold court-local origin is prefab placement minus prefab anchor. The current placement is (468,468), anchor (7.5,7.5), giving (460.5,460.5).
- Projection is 2:1 dimetric: x=(u−v)×64, y=(u+v)×32, then court origin (577,−160). Prefab world-pixel fields remain world pixels; they are never relabeled as tiles.
- Relief heights are metres and use the source `pxPerMeter` (24), `maxStepM` (0.4), outlines and ramp metadata. No automatic unit conversion occurs.
- NixieFX uses one ground tile/unit, +X aim, +Y up, +Z caster right. Cue `delayMs` is milliseconds; Nixie effect timeline duration and visual-patch delay/duration use source seconds. Sprite fps and normalized pivots are distinct from character atlas cell pivots in pixels.
- Document IDs are durable 1–100-character ASCII keys (`[A-Za-z0-9_-]`), assigned once by the author. Display names may change. Original catalog/object/character/skill/clip IDs remain verbatim in payloads. `provenance.legacyId` records the source identity, not a newly generated ID.
- A future mapping registry must map `(repository, format, legacyId)` to one durable document ID. No mapping/import tool or existing-production mapping is supplied in this task. Save prohibits changes to an existing document's kind, schemaVersion, format or legacyId. Source paths/hashes can be refreshed after source refactors without changing the ID. Deletion does not remove published snapshots.

## Runtime compatibility and schema policy

v1 is the original small authoring contract; v2 is an explicit format-tagged audited contract. The API serves the union schema plus `/contracts/v1/document.schema.json`, `/contracts/v2/document.schema.json` and `/v1/contracts`. New manifests carry each document's kind, schemaVersion and format; earlier immutable manifests remain untouched. Consumers must explicitly support the selected versions/formats and reject unsupported ones before applying content. Public release URLs remain pinned and immutable.

The runtime payload is stored under `data.payload` with original fields, order-sensitive arrays and numeric values. `data.bindings` maps the original binary paths to stored digests; it does not rewrite runtime JSON or install a loader. PostgreSQL JSONB normalizes key order/whitespace, so semantic JSON equality is the representation guarantee, not byte-for-byte original source text. Source SHA-256 identifies the exact audited source bytes separately.

No automatic v1→v2 conversion, downgrade, mechanical rule migration or schemaVersion change in-place is allowed. A future breaking contract requires a new format/version, explicit adapter work, compatibility tests and a new document identity/release. Existing releases never get rewritten. Additive optional metadata can evolve only with tests proving existing payloads stay accepted. A schema digest from `/v1/contracts` identifies the currently deployed schema; clients should pin it in validation evidence.
